# v0.1.19 — restore English entity suffixes after v0.1.17 regression

After v0.1.17 shipped with `_attr_name = None` (hoping HA would
translate `"model"` → `"型号"` via translation_key), users reported
that **entity suffixes disappeared entirely** — every entity was
displayed as just the device name ("ipc", "NVR") with no suffix at
all. This was strictly worse than v0.1.14's behaviour of showing
English suffixes.

This release restores the v0.1.14 entity name behaviour (English
suffix always visible) while keeping the v0.1.17 translation_key
machinery in place so HA *can* translate when its frontend honours
translation_key — which appears to not happen on the user's HAOS
2026.x, but is the right thing to attempt.

## Symptom — entity suffix lost after v0.1.17 / v0.1.18

```
On v0.1.14 / v0.1.15:
  ipc  CPU Usage              40.0%
  ipc  Device Name            0
  ipc  Firmware Version       V5.2.2 build 150518
  ipc  MAC Address            c4-2f-90-7c-61-60
  ...

On v0.1.17 / v0.1.18:
  ipc  DS-FB2127              (device name + serial, no English suffix)
  ipc  0                      (device name + device_name value, no suffix)
  ipc  V5.2.2 build 150518    (device name + firmware value, no suffix)
  ipc  c4-2f-90-7c-61-60     (device name + MAC value, no suffix)
  ...
```

The IPC page showed 16 entities (the v0.1.18 IPC additions +
existing 13) but each entity name was *just* the device name "ipc"
followed by the value. Same for NVR.

## Root cause

v0.1.17 set `self._attr_name = None` in `HikvisionSensor.__init__`,
intending that HA's translation_key machinery would supply the entity
suffix from the integration's translations file. The actual HA Core
2026.x behaviour for the `Entity.name` cached_property:

```python
@cached_property
def name(self):
    """Return the name of the entity."""
    if self._attr_name is not None:
        return self._attr_name
    if self.entity_description is not None:
        if self.entity_description.name is not None:
            return self.entity_description.name
    return None
```

When both `_attr_name` and `entity_description.name` are `None`,
`entity.name` returns `None`. HA's frontend then displays the entity
name as an empty string. With `_attr_has_entity_name = True`, this
means the rendered entity card shows just the device name
("ipc", "NVR") followed by the value, with no English suffix to
identify what the entity is.

The `translation_key` was set on `entity_description`, but HA's
frontend doesn't appear to apply it on the user's HAOS 2026.x for
this integration — likely because the integration's
`translations/zh.json` wasn't being read at the right time during
initial entity registration, or HA's frontend caches the resolved
name at registration time and doesn't re-read the translation files
on subsequent renders. Either way, translation_key-only entities
got no name.

## Fix

Two changes in `sensor.py`:

### 1. Restore `name=` on every `HikvisionSensorDescription` entry

Every entry in `IPC_SENSORS` (18 entries) and `NVR_SENSORS` (9
entries) now has both `name=` (English, e.g. "Model", "CPU Usage",
"IP Address") and `translation_key=` (e.g. "model", "cpu",
"ip_addr"). The `name` field is what HA's frontend displays; the
`translation_key` is metadata HA *may* use to translate when the
user's locale has a matching entry in `translations/<lang>.json`.

### 2. `HikvisionSensor.__init__` sets `_attr_name` to `description.name`

```python
def __init__(self, coordinator, entry, description):
    super().__init__(coordinator)
    self.entity_description = description
    # v0.1.19 — restore v0.1.14 behaviour: _attr_name is the English
    # suffix. v0.1.17 set _attr_name = None, hoping translation_key
    # would drive the name, but HA Core 2026.x short-circuits on
    # _attr_name=None and falls back to "just show the device name"
    # — which was strictly worse than v0.1.14's English suffix.
    if description.name:
        self._attr_name = description.name
    else:
        # Defensive fallback — none of the v0.1.19 entries actually
        # hit this branch (every description has name set), but the
        # Title-Case-from-key conversion ensures entities always have
        # a meaningful suffix even if a future refactor forgets to
        # set name on a new description.
        self._attr_name = description.key.replace("_", " ").title()
    # translation_key is still set — HA may overlay the translated
    # name on top of the English suffix on locale-aware installs.
    self._attr_translation_key = description.translation_key
    self._attr_unique_id = f"{entry.entry_id}_{description.key}"
    self._attr_device_info = coordinator.device_info
```

### 3. `_DynamicTableSensor.__init__` restores `_attr_name = name_suffix`

Per-channel and per-disk entities went through the same v0.1.17
regression. v0.1.19 restores `_attr_name = name_suffix` (English,
e.g. "Channel Label", "Motion", "Disk Name"). Translation_key is
still set for the same reason as the static sensors.

## What you should see

In HA on HAOS 2026.x after upgrading to v0.1.19:

- **Before v0.1.19 (v0.1.18 state):** IPC page showed 16 entities all
  suffixed with device name only ("ipc Model", "ipc Firmware",
  etc. — except the suffix was empty so it was just "ipc " followed
  by the value). NVR page showed 8 entities, all same issue.
- **After v0.1.19:** IPC page shows 16 entities each suffixed with
  "Model" / "CPU Usage" / "Device Name" / "Firmware Version" /
  "MAC Address" / "Manufacturer" / "Memory Usage" / "Memory Total" /
  "Storage Total" / "Storage Used" / "Uptime" / "Device Time" /
  "Network Type" / "IP Address" / "Subnet Mask" / "Gateway" /
  "Primary Video Codec" / "Secondary Video Codec". NVR page shows
  the 9 scalar entities plus 2 binary sensors.

For users on a zh-locale HA install where HA's frontend honours
`translation_key`, the suffixes will additionally translate to
"型号" / "CPU 使用率" / etc. — but the English suffix is always
there as a fallback.

## Why v0.1.16 / v0.1.17 didn't translate

Even though `translations/zh.json` is well-formed and 34 sensor keys
are present (verified locally), HA's frontend on the user's HAOS
2026.x doesn't apply the translation_key to entities that have a
`_attr_name` already set. Translation works only when
`_attr_name = None` AND `entity_description.name = None`. v0.1.17
tried that, but it short-circuits on a missing `name` to "just
device name" — strictly worse UX than English suffix.

A future v0.1.20+ could try a different mechanism (e.g. populating
the entity_registry's `translation_key` field directly via
`entity_registry.async_update_entity` after entity creation, or
using `homeassistant.helpers.translation.async_get_translation_key`
at runtime) — but for now v0.1.19's English suffix is the best
compromise: always meaningful, locale-aware when HA decides to
honour translation_key.
