# v0.1.2 — Dual-vendor (IPC + NVR) release

This release adds transparent support for Hikvision's **NVR / enterprise
recorder** product line alongside the existing IPC / PTZ support. The
integration auto-detects which product line is at the configured IP and
picks the right MIB subtree + entity set.

## What's new

- **Vendor auto-detect** — `device_info.async_identify_device` probes
  `.39165.1.1.0` (IPC model scalar) first; if it returns empty / NoSuchInstance,
  falls back to `.50001.1.3.0` (NVR serial scalar). The resolved vendor is
  stored on the coordinator and used to select the right MIB root, system
  scalars, and channel-table decoder.
- **NVR scalar sensors** — serial, IP, trap target, CPU frequency, channel
  count, active state, online state, and the two device-specific
  `.220` / `.221` leaves (temperature/load, traffic/IOPS).
- **NVR per-channel sensors** — label, motion flag (0/10), sub-stream size,
  bytes used (storage per channel).
- **NVR binary_sensor fallbacks** — NVRs do not expose `.24` (online) or
  `.25` (recording). `online` falls back to `coordinator.last_update_success`;
  `recording` falls back to "any channel `motion_flag > 0`" or "device
  `active_state == 1`".
- **`tools/snmp_probe.py` rewrite** — auto-detects vendor, prints a
  vendor-aware summary (NVR channel sub-table at `.50001.1.241.1.<col>.<row>.0`,
  IPC channel + disk sub-trees).
- **`docs/tested-devices.md`** — lists the 7 verified devices (4 IPC/PTZ on
  `.39165`, 3 NVR on `.50001`) with model, firmware, IP, and known quirks.
- **`docs/oid-reference.md` rewrite** — now documents both `.39165` (IPC)
  and `.50001` (NVR) layouts, and replaces the legacy pre-V5 IPC layout that
  didn't match what we actually see on real firmware.
- **README updates** — NVR entity table, dual-vendor explanation, fixed
  HACS URL (`kou147258/hikvision-snmp`).

## Breaking changes

None. Existing IPC / PTZ config entries continue to work — `coordinator.vendor`
defaults to `VENDOR_HIKVISION_IPC` when the IPC root responds, and the
existing IPC sensor set is unchanged.

## Renamed constants (internal only)

- `HIKVISION_PRIVATE_MIB_ROOT` → `HIKVISION_IPC_MIB_ROOT` (the generic name
  was misleading now that we have two product lines).

## New constants

- `HIKVISION_NVR_MIB_ROOT = "1.3.6.1.4.1.50001"`
- `NVR_SYSTEM_OIDS` — 22 scalar leaves under `.50001.1.<N>.0`
- `NVR_CHANNEL_OIDS` — 5 columns under `.50001.1.241.1.<col>.<row>.0`
- `VENDOR_HIKVISION_IPC`, `VENDOR_HIKVISION_NVR` — internal vendor identifiers
  (not exposed in the UI by design — see "Design notes" below).

## Design notes

- **No vendor picker in the UI.** All 7 verified devices are Hikvision, and
  the user explicitly asked for transparent dual-line support rather than
  a config-flow picker. The vendor is inferred once at setup and never
  re-displayed.
- **NVR `.230` / `.231` are device-level counters** — `.230.0` returns 1 if
  ≥1 channel is active; `.231.0` returns the count of online channels.
  These are not strict recording flags but are the closest device-level
  indicator in the `.50001` MIB.
- **NVR `.220` / `.221` are device-specific** — values from the three
  verified NVRs suggest `.220` is temperature ×10 (range 290..1130) and
  `.221` is traffic/IOPS (range 0..60). Both are exposed as raw int
  sensors; users can rename and re-unit in HA.

via the pysnmp-based `tools/snmp_probe.py` on Windows (with the known
Windows-pysnmp packet-loss caveat — see README).

## Upgrade notes

No data migration is required. Restart Home Assistant after upgrading.
