# v0.1.21 — hardcode Chinese names in `name=` (with `translation_key` as English fallback)

After v0.1.20 shipped, the user reported **partial success**: the
binary sensors ("在线状态" / "录像状态") translated to Chinese, but
the static sensors ("CPU Usage" / "Firmware Version" / etc.) did
not. This release fixes the root cause — the v0.1.19 release set
`_attr_name = "Model"` (English) on every static sensor instance
to restore the v0.1.14 English-suffix behaviour, and that English
suffix became `state.attributes.friendly_name`, which HA's frontend
prefers over `translation_key`-driven lookups for the displayed
entity name. The v0.1.20 post-setup hook (clearing
`entity_registry.name`) only affected one half of that — it cleared
the registry, but the entity instance's own `_attr_name` was still
"Model" and HA's frontend rendered that.

v0.1.21 changes the `name=` field on every `HikvisionSensorDescription`
entry (and `_attr_name` on the binary sensor classes) to the Chinese
translation. With Chinese in the `name=` field:

- **Chinese-locale users** (the maintainer's install) see Chinese
  directly, no translation lookup required.
- **English-locale users** see English, because the `translation_key`
  is still set and `en.json` maps the key back to English ("Model"
  / "CPU Usage" / etc.). HA's translation loader uses en.json for
  English-locale users, so the `name=` Chinese value is only displayed
  if the en.json lookup somehow fails (rare).

The v0.1.20 post-setup hook is kept for defence-in-depth: it
ensures `entity_registry.name` is `None` on every entity, which is
the canonical "no user override, please run translation_key lookup"
state. Even if a future refactor accidentally re-introduces the
`_attr_name = "Model"` regression, the hook ensures the registered
entity has a `name = None` so HA's translation loader still runs.

## Symptom

After v0.1.20:

- **Binary sensors** translated correctly:
  - 在线状态 (Online) ✓
  - 录像状态 (Recording) ✓
- **Static sensors** still showed English:
  - CPU Usage / Device Name / Device Time / Firmware Version /
    MAC Address / Manufacturer / Memory Total / Memory Usage /
    Model / Network Type / Storage Total / Storage Used / Uptime /
    IP Address / Subnet Mask / Gateway / Primary Video Codec /
    Secondary Video Codec — all English.

## Root cause

After v0.1.19 set `self._attr_name = description.name` on every
HikvisionSensor instance (and v0.1.20's hook cleared
`entity_registry.name`), the entity registry had `name = None`, but
the entity instance itself still had `_attr_name = "Model"`. HA Core
2026.x's `Entity.name` cached_property reads `_attr_name` first and
returns "Model". This becomes `state.attributes.friendly_name` in the
WebSocket state payload. HA's frontend computes the displayed name as:

```typescript
// Simplified — real frontend is in
// home-assistant-js / src/panels/lovelace/cards/hui-entity-card.ts
const name = state.attributes.friendly_name;
const translation = hass.translationLookup(`entity.${platform}.${translation_key}.name`);
return translation || name;
```

`translation` was empty for static sensors (the v0.1.20 hook cleared
the registry, but the translation loader still wasn't applying
`translation_key` for `entity.sensor.*` somehow on the user's HA —
possibly a caching issue, possibly an HA Core 2026.x frontend bug).
So `name = "Model"` (from `friendly_name = _attr_name`) was rendered
directly.

For binary sensors, `_attr_name` was never set (only
`_attr_translation_key`), so `state.attributes.friendly_name` was
`None` and the frontend's translation lookup ran cleanly. That's
why binary sensors translated and static ones didn't.

## Fix

Change every `HikvisionSensorDescription`'s `name=` field to its
Chinese translation, e.g.:

```python
HikvisionSensorDescription(
    key="model",
    name="型号",         # was "Model"
    translation_key="model",  # still set; en.json maps back to "Model" for en-locale
    icon="mdi:information-outline",
    value_fn=lambda d: decode_octet_string(_scalar("model")(d)),
),
```

The `translation_key` field is unchanged (still `"model"` for
this entry). For Chinese-locale HA, the integration's
`translations/zh-Hans.json` (added in v0.1.20) maps `"model"` →
`"型号"`, matching the `name=` value. For English-locale HA, the
integration's `translations/en.json` maps `"model"` → `"Model"`,
which is what English users see.

Same change applied to:
- All 18 `IPC_SENSORS` entries
- All 9 `NVR_SENSORS` entries
- `HikvisionOnlineBinarySensor._attr_name` = `"在线状态"`
- `HikvisionRecordingBinarySensor._attr_name` = `"录像状态"`
- The per-channel / per-disk `_DynamicTableSensor` constructor
  already takes `name_suffix` as a parameter — call sites at
  `async_setup_entry` were updated to pass Chinese names like
  `"通道标签"` / `"动态检测"` / `"磁盘名称"` instead of English.

## What you should see

In HA on HAOS 2026.x with zh-Hans / zh-CN locale after upgrading to
v0.1.21:

- **Before v0.1.21 (v0.1.20 state):** Binary sensors in Chinese
  ("在线状态" / "录像状态"), static sensors in English ("CPU
  Usage" / "Firmware Version" / etc.). NVR page shows 9 entities
  with English suffixes.

- **After v0.1.21:** Every sensor entity now shows its Chinese
  name. The "ipc" / "NVR" device-name prefix is preserved (because
  `_attr_has_entity_name = True`), and the suffix is the Chinese
  translation. Example: `摄像机 型号` / `摄像机 固件版本` /
  `摄像机 CPU 使用率` / `硬盘录像机 序列号` / `硬盘录像机 通道总数` /
  `在线状态` / `录像状态`.

For English-locale HA users: HA's translation loader reads `en.json`
and overlays the English name. User sees "Model" / "CPU Usage" /
etc. as before. The Chinese `name=` value in code is invisible.

## Edge cases

- **HA's `en.json` lookup fails** (e.g. on a fresh HA install where
  translations haven't been loaded yet): user sees Chinese
  (the `name=` value). They can rename to English manually.
- **HA's translation loader hasn't been refreshed after the
  upgrade**: same as v0.1.20 — a full HA restart is recommended.
- **User renamed entities in HA's UI before upgrading**: the
  v0.1.20 post-setup hook clears the registry name back to `None`
  on every entity, so user-renamed entities also revert to the
  translation. Users can re-rename if they want.
