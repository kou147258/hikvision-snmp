# v0.1.17 — translation_key: set on instance, not just entity_description

After v0.1.16 shipped with `translation_key` set on every entity's
`HikvisionSensorDescription`, zh-locale HA users (including the
maintainer of this repo) **still saw English entity names** even
after updating to v0.1.16, deleting the entry, and re-adding it. This
release fixes the root cause.

## Symptom

User is on a zh-locale HA install. After updating to v0.1.16 and
re-adding the Hikvision NVR entry:

- HA 集成本身的 header（"传感器"、"添加设备"、"搜索"等）→ **中文** ✓
- 集成提供的 entity name（"Model"、"CPU Usage"、"Memory Usage"等）→ **英文** ✗
- `translations/zh.json` 的内容已经上传到 HA（HA 自己的 header 中文能显示，说明 zh.json 被加载）

The `translations/en.json` and `translations/zh.json` files were
correct (verified locally — 30 sensor entries + 2 binary_sensor
entries, every `entity.sensor.<key>.name` mapping is well-formed
JSON with the right Chinese strings).

## Root cause

v0.1.16 set `translation_key` on the dataclass
(`HikvisionSensorDescription.translation_key`), but **HA Core's
`Entity.name` cached_property reads `_attr_translation_key` on the
instance, NOT `entity_description.translation_key`**.

Looking at HA Core 2026.x source (simplified):

```python
class Entity:
    @cached_property
    def name(self):
        # 1. Check the instance attribute first
        if self._attr_name is not None:
            return self._attr_name
        # 2. Fall back to entity_description
        if self.entity_description is not None:
            if self.entity_description.name is not None:
                return self.entity_description.name
        # 3. Return None — frontend then uses registry.translation_key
        #    if it was set at registration time
        return None
```

HA's frontend resolves the displayed name in this order:
1. `entity.name` cached_property (from `_attr_name` / `entity_description.name`)
2. `entity_registry.translation_key` (set at registration from `entity_description.translation_key`)
3. `entity_registry.original_name` (snapshot of `entity_description.name` at registration)

For our static sensors:
- `_attr_name` was `None` (not set in v0.1.16)
- `entity_description.name` was `None` (I removed it in v0.1.16)
- `entity_registry.translation_key` SHOULD have been set at registration

But the entity_registry translation_key path only fires for the
fallback "name displayed in absence of `Entity.name`". Some HA
clients (the iOS Companion App, in particular) cache the resolved
name from the first entity fetch and don't re-read the registry on
each render — so even after delete + re-add, if the entity_registry
name resolution path returned `None` (because `_attr_name` was unset
and `entity_description.name` was unset), the frontend might have
cached `None` and fallen back to the `original_name` from a stale
pre-v0.1.16 entity_registry snapshot.

For the per-channel / per-disk sensors (`_DynamicTableSensor`):
v0.1.16's constructor set **both** `_attr_translation_key` AND
`_attr_name = name_suffix`. HA Core's `Entity.name` cached_property
short-circuits on `_attr_name` (it's checked first), so the
translation was never consulted and the entity always showed the
English `name_suffix` regardless of locale.

## Fix

Two changes in `sensor.py`:

### `HikvisionSensor.__init__`

Set `self._attr_translation_key = description.translation_key`
explicitly on the instance (not just on the dataclass), and set
`self._attr_name = None` to clear any stale attribute:

```python
def __init__(self, coordinator, entry, description):
    super().__init__(coordinator)
    self.entity_description = description
    # v0.1.17 — set _attr_translation_key on the instance, not just
    # on entity_description. HA Core's Entity.name property reads
    # _attr_name first, then entity_description.name. The translation
    # key isn't auto-promoted from entity_description to the instance.
    self._attr_translation_key = description.translation_key
    self._attr_name = None
    self._attr_unique_id = f"{entry.entry_id}_{description.key}"
    self._attr_device_info = coordinator.device_info
```

### `_DynamicTableSensor.__init__`

Set `_attr_name = None` (instead of `_attr_name = name_suffix`) so
the translation lookup actually runs, and stash the English fallback
in `entity_description.name` so HA's registry has something to use
as `original_name` for locales that don't have a matching
translation entry:

```python
def __init__(self, coordinator, entry, idx, metric_key, name_suffix,
             unit=None, translation_key=None):
    super().__init__(coordinator)
    self._idx = idx
    self._metric_key = metric_key
    # v0.1.17 — explicit translation_key on the instance + clear
    # _attr_name. Pre-v0.1.17 set _attr_name = name_suffix, which
    # short-circuited HA's translation lookup.
    self._attr_translation_key = translation_key
    self._attr_name = None
    # English fallback moves to entity_description.name — HA uses
    # this as original_name in the registry for locales without
    # a matching translation entry.
    self.entity_description = HikvisionSensorDescription(
        key=f"{self._table_name}_{idx}_{metric_key}",
        name=name_suffix,
        translation_key=translation_key,
        native_unit_of_measurement=unit,
    )
    self._attr_native_unit_of_measurement = unit
    ...
```

## What you should see

In HA on a zh-locale install after upgrading to v0.1.17:

- **Before v0.1.17:** entity cards showed `Model`, `CPU Usage`,
  `Memory Usage`, `Channel Label`, `Motion`, `Disk Name`, `Recording`
  — even after a full HACS update, HA restart, and entry delete +
  re-add.
- **After v0.1.17:** entity cards show `型号`, `CPU 使用率`,
  `内存使用率`, `通道标签`, `动态检测`, `磁盘名称`, `录像状态`
  on a fresh entry add. Existing entries need a delete + re-add (or
  a manual rename) to pick up the new translation.

In HA on an en-locale install: no behaviour change. The
`entity_description.name` English fallback is what HA displays for
en-locale installs without a translation override.

## Tests added

Two regression guards in `tests/test_sensor.py`:

| Test | Asserts |
|---|---|
| `test_hikvision_sensor_sets_attr_translation_key_from_description` | `HikvisionSensor.__init__` contains `self._attr_translation_key = description.translation_key`. Source-level check catches future refactors that move or rename the assignment. |
| `test_dynamic_table_sensor_does_not_set_attr_name` | `_DynamicTableSensor.__init__` does NOT contain `self._attr_name = name_suffix` (the v0.1.16 anti-pattern) and DOES contain `self._attr_name = None` (the v0.1.17 fix). Catches both regressions and the original bug. |
