# v0.1.9 — `lookupMib=False` on all pysnmp calls

Adopted from the [OtisPresley/snmp-switch-manager](https://github.com/OtisPresley/snmp-switch-manager) reference integration.

## What changed

Added `lookupMib=False` to all three pysnmp primitive calls in
`snmp_client.py`:

```python
await getCmd(  ..., lookupMib=False)   # _do_get_raw
await bulkCmd(..., lookupMib=False)   # _do_bulk
await nextCmd(..., lookupMib=False)   # _walk_next (GETNEXT fallback)
```

## Why

The reference integration has this comment block in its
`engine.py` warmup code:

> "Home Assistant flags synchronous FS access (os.listdir/open)
> from pysnmp's MIB loader when it occurs on the asyncio loop
> thread. Preloading here ensures pysnmp will not hit the filesystem
> during async polling/walks."

That is the underlying issue: pysnmp 6.x tries to lazily load MIB
modules from disk the **first time** an OID is resolved. When that
happens on HA's event loop, pysnmp's blocking `open()` / `listdir()`
calls stall the loop and can cause:

- the SNMP request itself never gets dispatched (timeout)
- the response decode never completes (stale data on next refresh)
- HA logs warnings about synchronous filesystem I/O on the loop

`lookupMib=False` tells pysnmp to skip MIB resolution entirely and
treat OIDs as raw numeric arcs. For Hikvision this is exactly what
we want — every OID we use (`.1.3.6.1.4.1.39165.*` and
`.1.3.6.1.4.1.50001.*`) is **vendor-private** and pysnmp has no MIB
for it anyway. Skipping the lookup just removes the wasted FS round
trip on the event loop.

## What you should see

- **If your device was already reachable**: no behaviour change. SNMP
  walks were already getting through after the GETBULK/GETNEXT fallback
  chain; this just removes a small amount of FS work on the first call.
- **If your device was failing on the very first request of a new
  coordinator cycle**: this is the case that improves. The
  "Failed to connect via SNMP" you were seeing on the config-flow
  confirm step may have been caused (in part) by the lazy MIB load
  happening during the connection-test GET — a 1 s timeout vs a
  multi-second MIB-load + GET race. With `lookupMib=False`, the MIB
  load is skipped, the GET fires immediately, and the device's
  actual response time determines whether it succeeds.
