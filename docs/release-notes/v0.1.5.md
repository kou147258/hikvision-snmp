# v0.1.5 — Config flow rewritten with canonical `step_id="user"` pattern

If v0.1.4 still failed with
`Handler HikvisionSnmpConfigFlow doesn't support step basic` after you
verified HACS was on the new code, **this release fixes it definitively**.

## Root cause

The previous design used `step_id="basic"` for the first form, with a thin
`async_step_user` that delegated to `async_step_basic`. This pattern is
technically valid per HA's flow manager, but is fragile:

- If HA's flow manager resolves `step_id` against the **entry-point class**
  rather than the **current instance state**, the indirection can fail
  to be followed depending on how the integration was loaded (HACS cache
  vs. fresh install vs. dev-mode link).

The fix is to use the canonical pattern that every HA core integration
ships with: the **entry-point method IS the form-submit handler** for the
first step, using `step_id="user"`.

## Fix

`custom_components/hikvision_snmp/config_flow.py` now uses:

```python
async def async_step_user(self, user_input=None):
    if user_input is None:
        return self.async_show_form(
            step_id="user", data_schema=USER_DATA_SCHEMA_BASIC
        )
    self._basic = user_input
    return await self.async_step_snmp()
```

The `async_step_basic` indirection is removed. `step_id` now matches
`async_step_<id>` 1:1:

| step_id | method | form |
|---|---|---|
| `user` | `async_step_user` | Device basics (name, host, port, type) |
| `snmp` | `async_step_snmp` | SNMP credentials (v2c community / v3 user) |
| `confirm` | `async_step_confirm` | Connection test + entry creation |

Translation files (`strings.json`, `translations/en.json`,
`translations/zh.json`) updated correspondingly: the `step.basic.*`
keys are now `step.user.*`.

## Upgrade

After HACS picks up this release:

1. **HACS → Integrations → Hikvision SNMP** → ⋯ → **Redownload**
2. **Developer Tools → YAML → Restart** (full HA restart — `Reload` on
   the integration card is **not** sufficient because config-flow handlers
   are loaded at HA startup, not at integration load)
3. **Settings → Devices & Services → Hikvision SNMP** — if there's a
   partial entry from earlier attempts, ⋯ → **Delete**
4. **+ Add Integration → Hikvision SNMP** — the wizard now loads
