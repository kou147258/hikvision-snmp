# v0.1.6 — Fix `invalid_snmp_version` on every v2c submission

This release fixes the second-stage config-flow error that appeared right
after v0.1.5 made the wizard loadable:

```
Credentials do not match the selected SNMP version.
```

Every v2c submission (with a valid community string) was rejected with
that error.

## Root cause

Voluptuous's `Schema` rejects **extra keys** by default. The per-version
schema returned by `_snmp_data_schema("v2c")` was built like:

```python
vol.Schema({vol.Required(CONF_COMMUNITY): str})
```

When the user submitted the SNMP form, the dict always contained
`CONF_VERSION: "v2c"` (because the radio button is part of the form).
Voluptuous saw `version` as an extra key, raised `vol.Invalid`, and the
config flow's `except vol.Invalid` branch caught it and surfaced it as
the misleading `invalid_snmp_version` translation key.

## Fix

`_snmp_data_schema(version)` now returns a schema that **includes**
`CONF_VERSION` itself:

```python
def _snmp_data_schema(version):
    base = {vol.Required(CONF_VERSION, default="v2c"): vol.In(SNMP_VERSIONS)}
    if version == "v2c":
        return vol.Schema({**base, vol.Required(CONF_COMMUNITY): str})
    return vol.Schema({
        **base,
        vol.Required(CONF_USERNAME): str,
        ...
    })
```

The same schema is now used for both the form display AND the form-submit
validation, so voluptuous's extra-keys check never trips.

Also simplified `async_step_snmp` — the redundant `**cred_schema.schema`
spread is gone since `_snmp_data_schema(version)` now returns a complete
schema.

## What you should see now

1. Open **+ Add Integration → Hikvision SNMP**.
2. Step 1 (Device basics): name / host / port / device-type → Submit.
3. Step 2 (SNMP credentials): v2c is the default, type your community
   string → Submit.
4. Step 3 (Confirm): the integration runs `_test_connection` against your
   device. On success, the entry is created.

If you select v3 in step 2, the form re-renders with the v3 fields
(username / auth-protocol / auth-key / privacy-protocol / privacy-key).
Submitting a v3 form with missing required fields now shows the field-
level error rather than the misleading version-mismatch error.
